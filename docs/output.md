## Pipeline overview

The pipeline is built using [Nextflow](https://www.nextflow.io/) and processes data using the following steps:

- [FastQC](#fastqc) - Raw read QC
- [MultiQC](#multiqc) - Aggregate report describing results and QC from the whole pipeline
- [Pipeline information](#pipeline-information) - Report metrics generated during the workflow execution

### FastQC

<details markdown="1">
<summary>Output files</summary>

- `fastqc/`
  - `*_fastqc.html`: FastQC report containing quality metrics.
  - `*_fastqc.zip`: Zip archive containing the FastQC report, tab-delimited data file and plot images.

</details>

[FastQC](http://www.bioinformatics.babraham.ac.uk/projects/fastqc/) gives general quality metrics about your sequenced reads. It provides information about the quality score distribution across your reads, per base sequence content (%A/T/G/C), adapter contamination and overrepresented sequences. For further reading and documentation see the [FastQC help pages](http://www.bioinformatics.babraham.ac.uk/projects/fastqc/Help/).

### Signal analysis

<details markdown="1">
<summary>Output files</summary>

- `signal_analysis/index/<sample>/`
  - `*.index*`: nanopolish index sidecar files mapping basecalled reads to their raw FAST5 signal.
- `signal_analysis/eventalign/<sample>/`
  - `*.eventalign.txt`: per-read, per-k-mer current measurements aligned to the transcriptome. Large files (tens of GB on real runs).

</details>

Direct-RNA only. The nanopolish index is built whenever `--run_polya`, `--run_rna_modifications` or `--run_rna_methylation` is set. The eventalign step is expensive and only runs for the modification analyses; poly(A) uses the genome alignment instead and does not need it. Both modification tools below consume the same eventalign table, so the signal is aligned once.

Requires raw signal (FAST5) in the samplesheet `fast5` column and a transcript FASTA (`--transcript_fasta`).

### RNA modifications

<details markdown="1">
<summary>Output files</summary>

- `rna_modifications/<sample>/`
  - `*.m6a_sites.csv`: per-site m6A calls — transcript, position, k-mer, number of reads, modification probability and `mod_ratio` (stoichiometry, the fraction of molecules carrying the modification at that site).

</details>

Enabled with `--run_rna_modifications`. [m6anet](https://github.com/GoekeLab/m6anet) scores DRACH candidate sites with a neural network trained on known m6A positions. Per sample, in transcriptomic coordinates — it does not compare conditions. Sites need roughly 20 reads of coverage to be reliable.

### RNA methylation

<details markdown="1">
<summary>Output files</summary>

- `rna_methylation/dataprep/<sample>/`
  - `dataprep_<sample>/`: per-sample xPore intermediate (`data.json`, `data.index`, `data.readcount`, `eventalign.index`).
- `rna_methylation/diffmod/`
  - `diffmod.table`: per-site differential modification rate, p-value and z-score for each pairwise comparison of conditions.
  - `majority_direction_kmer_diffmod.table`: sites filtered to the majority modification direction per k-mer.

</details>

Enabled with `--run_rna_methylation`. [xPore](https://github.com/GoekeLab/xpore) fits a Bayesian mixture over the current distribution at each position and flags sites that differ between conditions. Replicates are grouped by the samplesheet `condition` column; a proper design needs at least 2 conditions with at least 3 replicates each.

Unlike m6anet, xPore is not m6A-specific — it detects any signal shift between conditions, and the chemical identity has to be inferred from the k-mer context.

### MultiQC

<details markdown="1">
<summary>Output files</summary>

- `multiqc/`
  - `multiqc_report.html`: a standalone HTML file that can be viewed in your web browser.
  - `multiqc_data/`: directory containing parsed statistics from the different tools used in the pipeline.
  - `multiqc_plots/`: directory containing static images from the report in various formats.

</details>

[MultiQC](http://multiqc.info) is a visualization tool that generates a single HTML report summarising all samples in your project. Most of the pipeline QC results are visualised in the report and further statistics are available in the report data directory.

Results generated by MultiQC collate pipeline QC from supported tools e.g. FastQC. The pipeline has special steps which also allow the software versions to be reported in the MultiQC output for future traceability. For more information about how to use MultiQC reports, see <http://multiqc.info>.

### Pipeline information

<details markdown="1">
<summary>Output files</summary>

- `pipeline_info/`
  - Reports generated by Nextflow: `execution_report.html`, `execution_timeline.html`, `execution_trace.txt` and `pipeline_dag.dot`/`pipeline_dag.svg`.
  - Reports generated by the pipeline: `pipeline_report.html`, `pipeline_report.txt` and `software_versions.yml`. The `pipeline_report*` files will only be present if the `--email` / `--email_on_fail` parameter's are used when running the pipeline.
  - Reformatted samplesheet files used as input to the pipeline: `samplesheet.valid.csv`.
  - Parameters used by the pipeline run: `params.json`.

</details>

[Nextflow](https://docs.seqera.io/platform-cloud/reports/overview) provides excellent functionality for generating various reports relevant to the running and execution of the pipeline. This will allow you to troubleshoot errors with the running of the pipeline, and also provide you with other information such as launch commands, run times and resource usage.
